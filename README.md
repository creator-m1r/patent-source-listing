# МИР 4D — Patent Source Listing

Универсальное macOS-приложение на Swift/SwiftUI для подготовки технического листинга исходного текста программных проектов, проверки его соответствия исходникам и анализа Git/unified diff.

## Возможности

### Формирование листинга
- выбор корневой папки проекта;
- рекурсивный обход вложенных каталогов;
- Unicode-дерево каталогов и файлов;
- определение языка программирования по расширению;
- исключение бинарных, медиа, build и служебных каталогов;
- логический порядок исходных файлов;
- полный относительный путь и язык перед каждым файлом;
- поля названия программы, проекта, версии, автора, правообладателя и организации;
- сохранение профилей организации/проекта;
- формирование единого RTF;
- моноширинный Courier New с настраиваемым размером;
- сквозная нумерация страниц средствами RTF;
- SHA-256 каждого включённого файла и всего набора;
- точный лимит готового RTF по байтам: по умолчанию 4 900 000 байт (4,90 МБ);
- автоматическая обратная проверка созданного RTF перед записью на диск;
- запрет сохранения RTF при обнаружении ошибки проверки.

### Достоверность исходного текста
Генератор не переводит и не форматирует идентификаторы исходного кода. Символы `\\`, `{`, `}` и Unicode безопасно кодируются средствами RTF. При выключенной очистке комментариев текст выбранных файлов перед экспортом не изменяется. После формирования RTF приложение повторно читает его как документ RTF и проверяет наличие исходного текста каждого файла.

### Очистка комментариев
Опциональная очистка комментариев выполняется **только над экспортируемой копией**. Исходные файлы проекта не изменяются. Режим очистки явно отражается в листинге.

### Состав листинга
По умолчанию исключаются служебные каталоги `.git`, `.github`, `.swiftpm`, `.vscode`, `.idea`, `DerivedData`, `build` и другие производные каталоги. Документация и конфигурационные файлы имеют отдельные переключатели и не удаляются из исходного проекта.

### Работа с diff
- анализ Git/unified diff;
- построение плана восстановления проекта без изменения диска;
- определение добавленных, измененных, удаленных и бинарных файлов;
- автоматическое создание вложенных каталогов;
- восстановление новых файлов из полного содержимого diff;
- применение patch к существующим файлам;
- поддержка переименования, когда исходный файл присутствует в папке восстановления;
- защита от абсолютных путей и `..` path traversal;
- предупреждения, если обычный diff не содержит достаточно данных для полного восстановления.

Важно: обычный diff не является полным архивом проекта. Измененный файл, для которого diff содержит только фрагмент изменений, невозможно достоверно восстановить без исходного файла. Программа не выдумывает отсутствующий код и сообщает об этом в отчете.

## Проверка качества
Проект содержит XCTest-регрессионные тесты для очистки комментариев, анализа diff, защиты путей, Unicode/RTF-экранирования и ограничения размера. GitHub Actions должен выполнять `swift build` и `swift test` на macOS 14.

## Запуск

Откройте `MIR4DPatentSourceListing.xcodeproj` в Xcode на macOS или откройте `Package.swift` и запустите target `MIR4DPatentSourceListing`.

Приложение автоматизирует техническую подготовку листинга. Перед подачей необходимо проверить актуальные требования Роспатента и конкретной патентной организации.
